# Story 9.3 — Pipeline de Geração Multi-Perfil

**Epic:** 9 — Livebooks Multi-Perfil & Enriquecimento de Speaker
**Status:** Ready for Review
**Points:** 8
**Priority:** P0 (Must)
**Executor:** @dev

---

## Descrição

Adaptar o pipeline `process-lecture` para gerar múltiplos perfis de livebook em sequência, usando os system prompts específicos por perfil e armazenando cada resultado na tabela `lecture_materials`. O pipeline deve receber a configuração de saída (`generation_configs`), iterar sobre os perfis selecionados, e gerar ebook + playbook para cada um.

A bio do palestrante deve ser injetada como contexto nos prompts de geração para personalizar o conteúdo.

---

## Acceptance Criteria

### AC1 — Leitura da configuração de saída
- [x] `process-lecture` lê `generation_configs` para a palestra
- [x] Se não existe config, usa defaults: `["junior_complete", "pleno_complete"]`
- [x] Parâmetro `content_format` (`topics` | `developed`) passado ao prompt

### AC2 — Geração iterativa por perfil (uma invocação por perfil)
- [x] Adotar padrão de **múltiplas invocações** (como chunks de transcrição):
  - Client envia `{ step: 'generate_profile', profile_type: 'junior_complete', content_type: 'ebook' }`
  - Edge Function gera 1 material por invocação e retorna `{ success, next_profile, next_content_type }`
  - Client itera automaticamente chamando próximo perfil/tipo
- [x] Cada invocação:
  ```
  1. Buscar system prompt: {content_type}_{profile_type}
  2. Injetar contexto: summary, topics, speaker.mini_bio, speaker.formation, event.publico_alvo
  3. Gerar markdown → salvar em lecture_materials
  4. Gerar imagens por capítulo (se ebook)
  5. Gerar PDF
  6. Atualizar status do perfil: completed
  7. Retornar próximo perfil/tipo a gerar (ou done)
  ```
- [x] Cada perfil é uma unidade independente: se um falha, os outros continuam
- [x] Status individual por perfil na tabela `lecture_materials`
- [x] Timeout seguro: cada invocação ~60-90s (bem dentro do limite de 300s)

### AC3 — Injeção de dados do speaker
- [x] Buscar dados do speaker vinculado à palestra: `mini_bio`, `formation`, `expertise_tags`, `featured_publications`
- [x] Se `mini_bio` está vazio, usar `bio` (campo legado)
- [x] Se nenhuma bio disponível, usar placeholder: "Informações do palestrante não disponíveis"
- [x] Incluir no prompt: nome, cargo, instituição, bio, formação, publicações

### AC4 — Progresso granular
- [x] `processing_progress` calculado como: `(perfis_completos / total_perfis) * 100`
- [x] Cada perfil atualiza `lecture_materials.status` em tempo real
- [x] Broadcast via Supabase realtime para UI receber updates

### AC5 — Controle de tamanho por perfil
- [x] Compacto: instruir prompt para ~3500 palavras
- [x] Completo: instruir prompt para ~7000 palavras
- [x] Registrar `word_count` real após geração em `lecture_materials`

### AC6 — Geração de PDF por perfil
- [x] Cada perfil gera seu próprio PDF separado
- [x] Naming: `{lecture_title}_{profile_type}.pdf` (ex: `ReformaObstetrica_junior_completo.pdf`)
- [x] Upload para `materials/{eventId}/{lectureId}/{profile_type}/ebook.pdf`
- [x] Atualizar `lecture_materials.pdf_url` com o path

### AC7 — Fallback e retry
- [x] Se geração de um perfil falha, marcar como `failed` e continuar com próximo
- [x] Permitir re-geração individual de perfil via API (não precisa reprocessar tudo)
- [x] Endpoint: `POST /process-lecture` com `{ action: 'regenerate', profile_type: 'senior_complete' }`

## Scope

**IN:**
- Adaptação do `process-lecture/index.ts` para loop multi-perfil
- Leitura de `generation_configs` e `system_prompts` por perfil
- Injeção de dados do speaker nos prompts
- Geração e upload de PDF por perfil
- Progresso granular e realtime updates
- Re-geração individual de perfil

**OUT:**
- UI de seleção (Story 9.2)
- Schema e migrations (Story 9.1)
- Speaker onboarding (Story 9.4)
- Geração de DOCX (futuro)
- Geração de podcast/áudio (futuro)

## Risks

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| Rate limiting do provider de IA (12 chamadas sequenciais) | Alto | Invocações separadas com delay natural entre chamadas client-side |
| Custo de tokens para 12 gerações por palestra | Médio | Monitorar `generation_metadata.tokens`; alertar organizador sobre custo estimado |
| Timeout da Edge Function | Alto | **Resolvido:** uma invocação por perfil (~60-90s cada), dentro do limite de 300s |
| Conteúdo inconsistente entre perfis da mesma palestra | Baixo | Mesmo summary/topics como base; variação vem apenas do system prompt |

## Technical Notes

- O loop de geração é sequencial (não paralelo) para evitar rate limits dos providers de IA
- Gemini 2.5 Flash para texto; Imagen 3 para imagens (mantém provider atual)
- System prompts devem ter variáveis interpoláveis: `{{speaker_name}}`, `{{speaker_bio}}`, `{{event_audience}}`, `{{word_target}}`
- Timeout por perfil: 120s para texto, 60s para imagens
- Estimativa: 6 perfis × 2 tipos × ~60-90s = ~12-18 min total (client-driven, não bloqueia Edge Function)
