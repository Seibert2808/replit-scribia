# Story 9.4 — Onboarding de Speaker com Biografia Enriquecida

**Epic:** 9 — Livebooks Multi-Perfil & Enriquecimento de Speaker
**Status:** Ready for Review
**Points:** 3
**Priority:** P1 (Should)
**Executor:** @dev

---

## Descrição

Enriquecer o fluxo de criação e aceite do palestrante para capturar dados de biografia estruturada que serão usados na geração dos livebooks. O organizador pode pré-preencher os dados, e o palestrante é incentivado (mas não obrigado) a completar sua biografia ao aceitar o convite.

---

## Acceptance Criteria

### AC1 — Form de criação do speaker enriquecido
- [x] Expandir `speaker-form-modal.tsx` com campos adicionais:
  - `mini_bio` (textarea, max 800 chars, com contador de caracteres)
  - `formation` (lista dinâmica: curso + instituição + ano, botão "Adicionar formação")
  - `expertise_tags` (input de tags com autocomplete)
  - `featured_publications` (lista de até 5 itens, texto livre)
  - `linkedin_url` (input URL com validação)
  - `pronouns` (select: ela/dela, ele/dele, elu/delu, outro)
- [x] Campos organizados em seções colapsáveis: "Dados Básicos" e "Perfil Profissional" (toggle)
- [x] Todos os novos campos são opcionais

### AC2 — Banner de incentivo à bio
- [ ] No speaker portal (`/speaker`), se `mini_bio` está vazio, exibir banner:
  ```
  ┌────────────────────────────────────────────────┐
  │ 📝 Complete sua biografia                      │
  │ Sua bio será incluída nos livebooks gerados    │
  │ a partir das suas palestras.                   │
  │                        [Completar perfil]      │
  └────────────────────────────────────────────────┘
  ```
- [x] Banner dismissível (salvar preferência em localStorage)
- [x] Reaparecer a cada 7 dias se bio ainda vazia

### AC3 — Tela de edição de perfil do speaker
- [x] Criar página `/speaker/profile` acessível do portal do palestrante
- [x] Formulário com todos os campos: bio, mini_bio, company, role, pronouns, linkedin, lattes, orcid
- [x] Pré-populado com dados existentes
- [x] Botão "Salvar" com feedback visual (check icon + "Salvo")
- [x] Speaker só pode editar seu próprio perfil (RLS via user_id)

### AC4 — Pré-preenchimento pelo organizador
- [x] Na `speaker-form-modal`, organizador pode preencher `mini_bio` e demais campos
- [x] Ao aceitar o convite, speaker vê dados pré-preenchidos e pode editar
- [ ] Indicador visual: "Preenchido pelo organizador" nos campos pré-populados (deferred)

### AC5 — Snapshot de bio por geração
- [x] Ao iniciar geração de livebook, salvar snapshot da bio atual em `lecture_materials.generation_metadata` (Story 9.3)
- [x] Bio editada depois não afeta livebooks já gerados (Story 9.3)
- [x] Campo `generation_metadata.speaker_snapshot` com: name, mini_bio, formation, expertise_tags (Story 9.3)

## Scope

**IN:**
- Expansão do form de speaker (organizador e palestrante)
- Banner de incentivo no portal do speaker
- Página de edição de perfil do speaker
- Snapshot de bio na geração

**OUT:**
- Foto de perfil upload (futuro)
- Consentimentos LGPD detalhados (futuro — está simplificado no MVP)
- Currículo Lattes/ORCID integration (futuro)

## Technical Notes

- Usar shadcn/ui: Textarea (com counter), TagInput (ou Combobox multiselect), Collapsible, Alert
- RLS: speaker pode UPDATE apenas `WHERE user_id = auth.uid()`
- Snapshot salvo como JSONB em `generation_metadata` — imutável após geração
- Design system: dark-first, purple brand conforme ADR-004
