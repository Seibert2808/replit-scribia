# Story 9.1 — Schema Multi-Perfil de Livebooks

**Epic:** 9 — Livebooks Multi-Perfil & Enriquecimento de Speaker
**Status:** Ready for Review
**Points:** 5
**Priority:** P0 (Must)
**Executor:** @data-engineer + @dev

---

## Descrição

Reestruturar o schema do banco de dados para suportar a geração de múltiplos perfis de livebook por palestra. Atualmente, `ebook_content` e `playbook_content` são colunas únicas na tabela `lectures`. O novo modelo precisa suportar 6 perfis independentes (Junior Compacto/Completo, Pleno Compacto/Completo, Senior Compacto/Completo) com seus respectivos conteúdos, imagens e status de geração.

Também inclui o enriquecimento do modelo de speaker com campos de biografia estruturada conforme o Briefing Técnico v1.1.1 (Camada 2).

---

## Acceptance Criteria

### AC1 — Tabela `lecture_materials`
- [x] Criar tabela `lecture_materials` com colunas (CHECK constraints ao invés de ENUM)
- [x] UNIQUE constraint em `(lecture_id, profile_type, content_type)`
- [x] RLS policies: organizer, speaker e lecture_access podem ler; service_role + super_admin podem escrever

### AC2 — Tabela `generation_configs`
- [x] Criar tabela `generation_configs` com configuração de saída por palestra (1:1)
- [x] Defaults: `["junior_complete", "pleno_complete"]`, content_format `developed`

### AC3 — Enriquecimento da tabela `speakers`
- [x] Adicionar campos: mini_bio, formation, expertise_tags, featured_publications, linkedin_url, lattes_url, orcid, profile_photo_url, pronouns
- [x] Campo `bio` existente mantido para compatibilidade

### AC4 — System Prompts por Perfil
- [x] 12 system prompts inseridos (6 ebook + 6 playbook)
- [x] Naming convention: `ebook_junior_compact`, `playbook_senior_complete`, etc.
- [x] Cada prompt segue especificações do Briefing Técnico com estruturas distintas por perfil
- [x] Prompts incluem variáveis: `{{title}}`, `{{speaker_name}}`, `{{speaker_bio}}`, `{{event}}`, `{{event_audience}}`, `{{content_format}}`

### AC5 — Migration retrocompatível
- [x] Colunas legadas intactas (ADD COLUMN IF NOT EXISTS, sem DROP)
- [x] Colunas legadas marcadas com COMMENT 'DEPRECATED: use lecture_materials'
- [x] Fallback de leitura será implementado no pipeline (Story 9.3)

---

## Scope

**IN:**
- Migration SQL com tabelas, enums, RLS, indexes
- Seed dos 12 system prompts baseados nos samples de referência
- Enriquecimento do modelo de speaker
- Fallback de leitura para dados legados

**OUT:**
- UI de seleção de perfis (Story 9.2)
- Lógica de geração no pipeline (Story 9.3)
- Onboarding de speaker com bio (Story 9.4)

---

## Risks

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| Migration falha em produção com dados existentes | Alto | Migration reversa preparada; testar em staging antes |
| ENUMs difíceis de alterar após criação | Médio | Usar CHECK constraints ao invés de ENUM types para flexibilidade |
| 12 system prompts difíceis de manter | Baixo | Naming convention clara; versionamento via `system_prompts.updated_at` |

## Technical Notes

- Usar `gen_random_uuid()` para PKs
- JSONB para campos flexíveis (formation, images, generation_metadata)
- Indexes: `lecture_materials(lecture_id)`, `generation_configs(lecture_id)`
- RLS: service_role para writes, authenticated para reads com policy por evento
