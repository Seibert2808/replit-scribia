# Story 9.2 — UI de Seleção de Perfis de Livebook

**Epic:** 9 — Livebooks Multi-Perfil & Enriquecimento de Speaker
**Status:** Ready for Review
**Points:** 5
**Priority:** P0 (Must)
**Executor:** @dev

---

## Descrição

Implementar a interface de seleção de perfis de livebook no dashboard do organizador. Antes de iniciar o processamento de uma palestra, o organizador deve poder selecionar quais dos 6 perfis deseja gerar, escolher entre conteúdo em tópicos ou desenvolvido, e configurar toggles editoriais (glossário, linha do tempo, quiz, mapa de conexões).

Também inclui a visualização e download dos materiais gerados por perfil no lecture detail.

---

## Acceptance Criteria

### AC1 — Configuração pré-processamento
- [x] No `lecture-detail-dashboard`, antes do botão "Processar", exibir seção "Configuração de Saída"
- [x] Checkbox grid com os 6 perfis organizados em matriz 3×2:
  ```
  ┌─────────────────────────────────────────┐
  │        Compacto         Completo        │
  │ Junior    [x]             [x]           │
  │ Pleno     [ ]             [x]           │
  │ Senior    [ ]             [ ]           │
  │                                         │
  │ Formato: ○ Tópicos  ● Desenvolvido     │
  └─────────────────────────────────────────┘
  ```
- [x] Defaults: Junior Completo + Pleno Completo marcados (conforme briefing)
- [x] Pelo menos 1 perfil deve estar selecionado para habilitar processamento
- [x] Toggles editoriais colapsáveis: glossário, linha do tempo, quiz, mapa de conexões

### AC2 — Configuração a nível de evento
- [ ] Na página de configurações do evento, seção "Perfis Padrão de Livebook" (deferred — pode ser feito depois)
- [ ] Mesma interface de seleção, mas aplica como default para todas as palestras
- [ ] Palestras herdam config do evento; override por palestra é visual (badge "customizado")

### AC3 — Persistência
- [x] Salvar configuração na tabela `generation_configs` (Story 9.1)
- [x] Carregar configuração existente ao abrir o lecture detail
- [x] Se não existe config, carregar defaults do evento

### AC4 — Visualização de materiais por perfil
- [x] No lecture detail, accordion por perfil gerado com expand/collapse
- [x] Cada perfil mostra: preview do markdown + botão download PDF
- [x] Badge de status por perfil: "Pendente" / "Gerando..." / "Pronto" / "Falhou"
- [x] Perfis não selecionados aparecem em cinza com "Não solicitado"

### AC5 — Indicador de progresso multi-perfil
- [x] Progress bar mostra progresso geral (ex: "3/6 perfis gerados")
- [x] Cada perfil tem status indicator individual
- [x] Realtime updates via Supabase subscription na tabela `lecture_materials`

---

## Scope

**IN:**
- UI de seleção de perfis (checkbox grid)
- Configuração a nível de evento (defaults)
- Tabs/accordion de visualização por perfil no lecture detail
- Persistência em `generation_configs`
- Progress indicators multi-perfil

**OUT:**
- Lógica de geração no backend (Story 9.3)
- Schema e migrations (Story 9.1)
- Speaker onboarding (Story 9.4)

---

## Risks

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| Organizador não entende diferença entre perfis | Médio | Tooltips com descrição de público-alvo de cada perfil |
| Config a nível de evento conflita com override por palestra | Baixo | Badge visual "customizado" + fallback claro para defaults |

## Technical Notes

- Usar componentes shadcn/ui existentes (Checkbox, RadioGroup, Accordion, Badge, Progress)
- Design system: dark-first, purple brand, Syne + DM Sans
- Realtime subscription: `supabase.channel('lecture_materials').on('postgres_changes', ...)`
- Responsivo: grid 3×2 em desktop, stack vertical em mobile
