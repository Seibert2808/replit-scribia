# Story 10.1 — Schema de Engajamento & Analytics do Palestrante

**Epic:** 10 — Painel do Palestrante — Dashboard de Leads & Gestão

## Story

Como **palestrante**, quero que o sistema rastreie detalhadamente as interações dos participantes com minhas palestras (escuta de áudio, downloads de ebooks, compartilhamentos), para que eu possa ver quem na plateia virou lead e qual o nível de engajamento de cada pessoa.

---

## Descrição

Criar as tabelas de banco de dados e políticas RLS necessárias para suportar o painel do palestrante. O schema deve capturar eventos de engajamento granulares (event-sourcing), arquivos enviados pelo speaker, solicitações de mudança e frases de destaque — formando a base de dados para todas as stories do Epic 10.

## Acceptance Criteria

### AC1 — Tabela `engagement_events` (event-sourcing de interações)
- [x] Criar tabela `engagement_events`:
  ```sql
  CREATE TABLE public.engagement_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    lecture_id UUID NOT NULL REFERENCES public.lectures(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES public.user_profiles(id) ON DELETE CASCADE,
    event_type TEXT NOT NULL CHECK (event_type IN (
      'audio_play',        -- Iniciou escuta do áudio
      'audio_complete',    -- Ouviu 100% do áudio
      'ebook_download',    -- Baixou o ebook (PDF)
      'playbook_download', -- Baixou o playbook (PDF)
      'card_share',        -- Compartilhou card nas redes sociais
      'page_view'          -- Visualizou a página da palestra
    )),
    metadata JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
  );
  ```
- [x] Campo `metadata` armazena dados específicos por tipo de evento:
  - `audio_play`: `{ "progress_percent": 75, "duration_seconds": 1200 }`
  - `audio_complete`: `{ "total_duration_seconds": 1920 }`
  - `ebook_download`: `{ "profile_type": "pleno_compact", "format": "pdf" }`
  - `playbook_download`: `{ "profile_type": "senior_complete", "format": "pdf" }`
  - `card_share`: `{ "platform": "instagram" | "linkedin" | "whatsapp" | "other" }`
  - `page_view`: `{ "source": "portal" | "direct_link" }`
- [x] Índices: `(lecture_id, user_id)`, `(lecture_id, event_type)`, `(created_at)`
- [x] Permite múltiplos eventos do mesmo tipo por usuário (log de eventos)

### AC2 — View materializada `lecture_leads` (score de engajamento)
- [x] Criar view `lecture_leads` que agrega engagement_events por (lecture_id, user_id):
  ```sql
  CREATE OR REPLACE VIEW public.lecture_leads AS
  SELECT
    la.lecture_id,
    la.user_id,
    up.full_name,
    up.email,
    up.avatar_url,
    -- Flags de engajamento
    EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'audio_complete') AS audio_completed,
    MAX(CASE WHEN ee.event_type = 'audio_play' THEN (ee.metadata->>'progress_percent')::int ELSE 0 END) AS audio_max_progress,
    EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'ebook_download') AS ebook_downloaded,
    EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'playbook_download') AS playbook_downloaded,
    EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'card_share') AS card_shared,
    -- Score de engajamento (0-100)
    (
      CASE WHEN EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'audio_complete') THEN 35 ELSE
        LEAST(30, (COALESCE(MAX(CASE WHEN ee.event_type = 'audio_play' THEN (ee.metadata->>'progress_percent')::int END), 0) * 30 / 100))
      END
      + CASE WHEN EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'ebook_download') THEN 30 ELSE 0 END
      + CASE WHEN EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'playbook_download') THEN 15 ELSE 0 END
      + CASE WHEN EXISTS(SELECT 1 FROM engagement_events ee WHERE ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id AND ee.event_type = 'card_share') THEN 20 ELSE 0 END
    ) AS engagement_score,
    -- Temperatura do lead
    -- hot (>=70), warm (>=30), cold (<30)
    MIN(ee.created_at) AS first_interaction_at,
    MAX(ee.created_at) AS last_interaction_at
  FROM public.lecture_access la
  JOIN public.user_profiles up ON up.id = la.user_id
  LEFT JOIN public.engagement_events ee ON ee.lecture_id = la.lecture_id AND ee.user_id = la.user_id
  GROUP BY la.lecture_id, la.user_id, up.full_name, up.email, up.avatar_url;
  ```
- [x] Computed field `lead_temperature`:
  - `hot` (LEAD QUENTE): score >= 70 (ouviu + baixou + compartilhou)
  - `warm` (LEAD MORNO): score >= 30 (interagiu parcialmente)
  - `cold` (LEAD FRIO): score < 30 (apenas visualizou)

## Technical Notes

- **Event-sourcing:** A tabela `engagement_events` é append-only. Nunca editar/deletar eventos — calcular estado atual a partir da timeline de eventos.
- **Score weights:** audio_complete=35pts, ebook_download=30pts, card_share=20pts, playbook_download=15pts. Total máximo: 100pts.
- **Lead temperature:** hot >= 70 (ações completas), warm >= 30 (parcial), cold < 30 (visualização).
- **Storage:** Bucket `speaker-uploads` separado do `materials` existente. Path: `{lecture_id}/{speaker_id}/{filename}`.
- **Naming:** Migration file: `20260504100000_engagement_analytics_schema.sql`
- **View vs Materialized View:** Usar VIEW regular inicialmente. Se performance se tornar um issue (>1000 participantes por palestra), migrar para MATERIALIZED VIEW com refresh periódico.
